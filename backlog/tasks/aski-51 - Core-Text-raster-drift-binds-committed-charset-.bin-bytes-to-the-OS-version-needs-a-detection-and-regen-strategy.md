## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Gate-stability risk logged in the Discoveries entry of 2026-06-10, "Core Text raster output drifts across macOS updates; committed .bin bytes are OS-version-bound" (docs/Research/Discoveries.md).

The entry records: while regenerating ShapeData/*.bin for the v2 format bump (ASTSK-28), the Step-0 determinism pre-check failed - 6 of 10 committed v1 bins (standard, dots, cross, diamond, diagonal, mixed) could not be byte-reproduced on the then-current macOS. Core Text anti-aliasing had shifted some glyph coverage by <= 1e-4 in brightness (single gray levels on a few pixels) since the bins were built on 2026-05-06. Scalar sort order survived and the full snapshot suite stayed green, so matching was unaffected at that magnitude. A frontier-search confirmed this is known platform behaviour: image-snapshot communities hit it on minor OS updates, and no CoreGraphics/CTFont API pins rasterizer output across releases. The four clean sets include braille, generated by the vendored BrailleRasterizer, which is immune by construction. Drift was per-glyph rather than per-font-fallback: minimal (ASCII) was clean while diagonal (/\X, also ASCII) drifted.

Why it is a risk rather than a curiosity: the committed .bin bytes are an input to the shipped matcher and to byte-diff-guarded regeneration steps, so a large enough OS-side drift can either flip snapshot goldens or silently change glyph selection, and today nothing detects it except a manual regen. The repo has no OS-version stamp on the bins and no scheduled determinism check, so the failure mode is discovered by accident at the next regen.

This spike defines detection and a regen policy; it does not commit to vendoring a rasterizer up front. The entry already names the escalation trigger: "a future regen on a newer macOS shows drift > 1e-3, flips any snapshot test, or changes the brightness sort permutation - that is the trigger to vendor a deterministic glyph rasterizer (or commit per-OS golden rasters) instead of relying on Core Text stability."

Touches: Tools/BuildStandardVectors/, Sources/Aski/Resources/ShapeData/*.bin, Sources/Aski/CharacterSets/RasterizedCharacterSet.swift (Core Text rasterization path), Sources/Aski/CharacterSets/Braille/ (the immune-by-construction reference point).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Current drift is measured: regenerate all ten ShapeData/*.bin on the current macOS and report per-set and per-glyph deviation against the committed bytes, plus whether the brightness sort permutation changed
- [x] #2 A detection strategy is chosen and recorded - for example a tolerance-based determinism check runnable on demand, an OS/toolchain version stamp carried with the bins, or an explicit decision to keep detection manual with a stated reason
- [x] #3 A regen policy is written down: when the bins are allowed to be regenerated, what tolerance is acceptable without treating it as a behaviour change, and what must be re-verified (snapshot suite, sort permutation, selection goldens)
- [x] #4 The escalation trigger from the 2026-06-10 entry (drift > 1e-3, a flipped snapshot test, or a changed brightness sort permutation) is either shown not to have fired or, if it has, a follow-up task is filed for a deterministic rasterizer or per-OS golden rasters
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Refactor BuildStandardVectors into an in-memory encoder so audit and write paths share exactly one generator.
2. Add an on-demand audit mode that compares fresh bytes with committed v3 bins by Unicode scalar and reports byte identity, per-glyph max deltas, and brightness-order changes without modifying resources.
3. Freeze a tolerance and escalation policy in tests and documentation, including OS, Xcode, and Swift provenance.
4. Run the audit on this host, commit its result artifact, apply the trigger mechanically, and update the research registry and Backlog record.
5. Run focused tests and the full repository gate before the local commit.
<!-- SECTION:PLAN:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Implemented a read-only, scalar-keyed audit for all ShapeData v3 channels and a frozen regeneration policy. The one-shot run at ef1c08e on macOS 26.6.2, Xcode 26.5, and Swift 6.3.2 found all 10 sets and 414 glyphs byte-identical, with zero component drift and no brightness-order change. The escalation trigger did not fire; no resource regeneration or follow-up rasterizer task is required.
