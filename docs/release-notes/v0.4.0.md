# Aski v0.4.0

`v0.4.0` is a pre-1.0 default-output release. The default gamut mapper changes from adaptive L0 to CSS Ray Trace.

## Highlights

- **Ray Trace gamut mapping is now the default.** `ASCIIConverter.gamutMapping` defaults to `.rayTrace`.
- **Legacy comparison remains available.** Pass `gamutMapping: .adaptiveL0` to compare against the previous default.
- **sRGB and Display P3 both use shipped Ray Trace behavior.** `GamutMapping.rayTraceToSRGB(_:)` and `GamutMapping.rayTraceToDisplayP3(_:)` share one implementation with target-specific color conversion boundaries.
- **The lab now measures production Ray Trace.** `gamut-sweep` `rayTrace` rows route through production wrappers, while `baseline_policy` remains `adaptiveL0`.

## Visual Tradeoff

Aski v0.4.0 intentionally changes the default gamut mapper from adaptive L0 to CSS Ray Trace for stronger lightness and hue preservation on out-of-gamut OkLCh stress cases. Color.js still documents its `css` method as binary-search CSS gamut mapping, so this is an Aski default choice rather than a claim of ecosystem consensus. The main visible tradeoff is tighter boundary mapping that can desaturate extreme Display P3 yellows.

## Migration

Most callers do not need a source change. If exact `v0.3.x` gamut behavior matters, pass `gamutMapping: .adaptiveL0` explicitly:

```swift
let converter = ASCIIConverter(
    characterSet: StandardCharacterSet.standard,
    palette: BuiltInPalette.fullColor,
    gamutMapping: .adaptiveL0
)
```

## Documentation

- **Research registry (ASTSK-9).** `docs/Research/` notes now carry YAML front-matter, and `swift run BuildResearchIndex` generates the README index plus a machine-readable `docs/Research/index.json` (enforced by `ResearchRegistryTests`). Library behavior and rendered output are unchanged.
