# Aski v0.8.0

`v0.8.0` is the second release on this repository's public history. It corrects how raster
output interprets cell colors, validates GIF loop counts, adds `aski render` options for the
algorithm, dither strength and palette, and adds a CLI packaging script and a Swift Package
Index documentation config. The full list is in the [changelog](../../CHANGELOG.md).

## Highlights

- **New `aski render` options (ASKI-82).** `--algorithm logPolar|dotMatrix`, `--coverage 0...1`
  and `--palette fullColor|monochrome`. The defaults (`logPolar`, `0`, `fullColor`) produce the
  same output as before. `--write-manifest` records the three values as optional fields in the
  existing v1 render manifest schema.
- **Character-art recipes.** The [recipes guide](../guides/character-art-recipes.md) gives three
  CLI recipes with their exact commands and the PNGs they produce from the bundled Carina image.
  Each uses at least one of the new options above.
- **Glyph cycling with `dotMatrix` (ASKI-81).** Animation glyph cycling now changes glyphs under
  `dotMatrix`; candidates after the base pick are the glyphs nearest in ink density. The base frame
  is unchanged.
- **CLI text output to `/dev/null` and `/dev/stdout` (ASKI-83).** `aski render --output` can
  discard text or send it to a pipe while `--render-png` writes the image.
- **Updated `logPolar` guidance (ASKI-79).** The documentation now recommends `logPolar` only with
  the `standard` and `braille` character sets, and points to `dotMatrix` for the sets it renders
  blank or with a few repeated glyphs. Converter output did not change.
- **README hero (ASKI-15).** The README image is now a default-settings render from the current
  build, with the command that produces it.

## Behavior and source changes

- **Raster colors change (ASKI-3).** ASCII, tile and effects rendering previously interpreted
  encoded sRGB and Display P3 cell colors as Generic RGB. They now use the grid's declared color
  space, and `AskiRenderEngine` converts colors when its output gamut differs from the grid's.
  Raster colors change, including mid-gray neutrals. Glyph selection and attributed-string colors
  do not change. Review saved renders and remove any compensation for the old colors.
- **CLI colors are sRGB.** `--background`, `--mask-fallback-color` and `--mask-ground` are built
  in sRGB. `aski render --background "#808080"` now writes `#808080` pixels; it wrote `#929292`
  before. The value now matches the `#RRGGBBAA` value recorded in the manifest.
- **GIF loop counts are validated (ASKI-8).** `ASCIIGIFEncoder.write` accepts `loopCount` in
  `0...32767` (`0` is infinite, `1` plays once) and throws the new
  `GIFEncodeError.invalidLoopCount(_:)` for other values before it creates the file. This new
  enum case is a source break for exhaustive `switch` statements over `GIFEncodeError`.
  `GIFEncodeReport.loopCount` now reports the value read back from the written file.
- **Other special CLI destinations are rejected.** Apart from `/dev/null` and `/dev/stdout`,
  special files such as FIFOs are rejected as `--output` before any output changes. PNG and
  manifest destinations must be regular files.

No other public declarations in the `Aski` module were added, removed or changed since `v0.7.0`.

## Upgrading

Pin the release exactly:

```swift
.package(url: "https://github.com/BigCactusLabs/Aski.git", exact: "0.8.0"),
```

Aski is pre-1.0; an exact pin keeps upgrades deliberate. Then:

1. Add a branch for `GIFEncodeError.invalidLoopCount` to any exhaustive `switch` over
   `GIFEncodeError`, and handle source GIFs whose loop count is outside `0...32767`.
2. Re-render and review saved raster output, and remove any manual color compensation for the
   previous Generic RGB interpretation. Build background, mask-fallback and ground colors with
   explicitly tagged `CGColor` values such as `CGColor(srgbRed:green:blue:alpha:)`.
3. Regenerate CLI renders made with `--background`, `--mask-fallback-color` or `--mask-ground`
   before comparing them with new output.

The [migration notes](../../Sources/Aski/Aski.docc/Migrating-to-A1.md) cover these steps with
links to the rendering, video and command-line guides.

## For contributors

- **CLI candidates.** `just package-cli <new-dir>` builds an arm64-only, relocatable `aski`
  candidate, checks its resources, smoke-tests a relocated copy and writes an archive with
  `SHA256SUMS`. It does not run the acceptance gates or publish anything. See the
  [distribution guide](../guides/distribution.md).
- **Swift Package Index.** `.spi.yml` declares `Aski` as the documentation target.
- **DocC Markdown export path.** `./Scripts/validate-docc.sh --emit-markdown` no longer writes to
  `/tmp/aski-docc-markdown`, which the v0.7.0 notes describe. It prints the directory it created;
  pass `--output-dir <new-dir>` for a fixed location.
- **Script tests.** `just test-infra` runs portable regression tests for the doctor, DocC and
  Metal-restoration scripts with Python 3. It does not replace `just check`.
- **Render goldens.** Goldens changed by ASKI-3 were re-recorded on macOS 27.0.1 / Xcode 27.0 /
  Swift 6.4. Exact raster output also depends on the host machine; see the
  [toolchain and snapshot baseline](../../CONTRIBUTING.md#toolchain-and-snapshot-baseline).
