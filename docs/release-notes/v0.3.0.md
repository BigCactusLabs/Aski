# Aski v0.3.0

Additive color-pipeline release after `v0.2.0`. This release flips no defaults and does not regenerate snapshots.

## Highlights

- **`PaletteMatchingPolicy.oklabHyAB`** adds an experimental palette-matching option that scores city-block lightness plus Euclidean chroma. The default remains `.oklabEuclidean`.
- **`RenderCompositionPolicy.extendedLinearPerGamut`** adds an opt-in renderer composition path that composites in the target gamut's own linear-light color space: `linearSRGB` for sRGB output and `linearDisplayP3` for Display P3 output. The default remains `.encodedDisplay8Bit`.
- **Renderer propagation fixes** keep the composition policy intact through animation frame materialization and the effects raster path.
- **`cbrtf` production switch reconciliation** marks the already-shipped OKLab cube-root correction as resolved in the deferred-work review docs.

## Migration

No action is required for callers staying on defaults. `v0.3.0` preserves `v0.2.0` default palette matching, color sampling, and encoded-display compositing behavior.

Callers can opt into the new behavior explicitly:

- Use `paletteMatching: .oklabHyAB` to try the experimental HyAB-style OKLab distance.
- Use `composition: .extendedLinearPerGamut` to render alpha compositing in the output gamut's linear-light space.

## What's NOT in v0.3.0

- Linear-light sampling is not the default in `v0.3.0`.
- Ray Trace gamut mapping is not the production default.
- `PaletteMatchingPolicy.helmlabMetric` is not implemented; the original quick-metric framing was later paused because Helmlab is a separate color space, not a distance function on OKLab values.
